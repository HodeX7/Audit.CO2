# Decisions

One line each: decision, why, date. Newest at the bottom of each owner's section.

## Ujjwal (Ingestion & Ledger)

- Quantities, factors and results are stored as decimal strings (TEXT), never floats. Why: deterministic math, no float drift. 2026-11-03
- Honesty rules are enforced by SQLite triggers (no DELETE anywhere, immutable evidence, append-only events/approvals/calculations, gap close needs a human, period close needs a recorded APPROVE). Why: they hold even if an agent writes raw SQL. 2026-11-03
- The stored excerpt is the full source line(s) from the document, and the locator (page/line) is computed by code. The proposer's page number is only a search hint. Why: the evidence is the document's own words, not the model's paraphrase. 2026-11-03
- A claim is accepted only if its number AND unit appear in its excerpt; site and period each need their own excerpt (exactly one known site; exactly one month). Excerpts shorter than 8 characters are refused. Why: blocks an excerpt that exists but proves something else. 2026-11-03
- Proposer order in `auto` mode: cache → LLM (if a key is set) → rules. The rules proposer exists so judges can reproduce the demo with no key, and as a fallback on rate limits. Both go through the same verifier. 2026-11-03
- ~~The committed seed cache was produced by the rules proposer and is labelled `rules-v1`.~~ (Superseded: re-saved with Nemotron 3 Ultra, see below.) With an NVIDIA key, `carbonroom seed --refresh-cache --proposer llm` regenerates it with the LLM (labelled `llm:nvidia:<model>`). Why: no key was available while building; we label honestly. 2026-11-03
- ~~Default NVIDIA model `meta/llama-3.3-70b-instruct`~~ Superseded the same day: with a real key, that model returned HTTP 410 (retired) and `nvidia/nemotron-3-super-120b-a12b` and `deepseek-ai/deepseek-v3.1` returned 404, although the first is in GET /models. So there is no default model: `LLM_MODEL` must be set, chosen with `carbonroom llm probe` (one tiny call per listed chat model) and `carbonroom llm bench`. Without it, `auto` uses the cache, then rules. 404/410/401/403 are not retried, and bench skips that model's remaining documents. 2026-11-03
- NVIDIA calls: temperature 0, throttled to `CR_LLM_RPM`=35/min (free tier is about 40), retries on 429/5xx/timeouts honouring Retry-After, max 5 attempts. Anthropic calls send no temperature or response_format (its OpenAI-compat layer rejects them on recent models). 2026-11-03
- Anthropic base URL override is `CR_ANTHROPIC_BASE_URL`, not `ANTHROPIC_BASE_URL`. Why: Claude Code may set the latter on our machines. 2026-11-03
- A corrected document ("Replaces bill: X", proven by an excerpt) marks X's document `superseded_by` and records `replaces_activity_ids` on the new row. Ingestion does NOT change the old row's status. Why: the checker owns decisions, and this is what makes the "false done" reopen visible. 2026-11-03
- Two documents claiming the same thing (INV-204 vs INV-204B) are both stored; ingestion opens no conflict gap. Why: honesty rule 2 (never pick one silently); detection is the checker's job. 2026-11-03
- The cloud provider is a `sites` row with `kind='cloud'` (owner Dev, room `cr-cloud`, grid SRVC for us-east-va). Why: its gaps route like any site's; Scope 3 Cat 1 stays separate in the report. 2026-11-03
- New table `expected_documents`; diesel is `as_delivered`, so months without a delivery are not "missing". Why: missing-bill detection without guessing. 2026-11-03
- Seed files are referenced in place; every other upload is copied to `data/store/<sha256><ext>` (gitignored). Why: evidence can't change or disappear after it is recorded. 2026-11-03
- Units: MWh→kWh ×1000, Dth/MMBtu→therms ×10, litres→US gallons ÷3.785411784 (exact definition), rounded to 0.001 gal. Gas volume units (ccf, m³) are refused, because they need the utility's heat content. 2026-11-03
- Hand-off with Akshar: synchronous `carbonroom ingest <file> --from --room --thread --message --gap --json` (recommended), or the `data/inbox/<room>/` watch folder with a `.meta.json` sidecar. 2026-11-03
- CLI plugin hook: teammates add commands in `carbonroom/{calc,check,report,switchbridge}/cli.py` via `register(subparsers)`, so nobody edits `cli.py` and merges stay clean. 2026-11-03
- Seed PDFs are generated with reportlab `invariant` mode, so the bytes and hashes are reproducible and cache keys stay valid. 2026-11-03
- `carbonroom seed` resets by removing the database file, not with SQL DELETE. 2026-11-03
- September 2026 is loaded `OPEN`/`UNVERIFIED`, like October. Ingestion never verifies or closes a period. 2026-11-03
- `carbonroom llm probe` (25 + 7 listed chat models): most answer HTTP 404 "Not found for account" on the free key. Working: google/gemma-4-31b-it (28 s), meta/llama-3.2-90b-vision-instruct (102 s), mistralai/mistral-large-4-1t-a52b (3 s, but timed out later), and nvidia nemotron-3-nano-omni-30b-a3b-reasoning, nemotron-3-ultra-550b-a55b, nemotron-3.5-bolt-e4b, nemotron-3.5-lightning-30b-a3b, nemotron-3.5-super-vl-120b-a12b. 2026-11-03
- First `carbonroom llm bench` on the 13 seed documents: nemotron-3-ultra-550b-a55b 12/13 exact (about 18 s/doc), nemotron-3.5-bolt-e4b 11/13 (about 7 s/doc), nemotron-3.5-lightning returned no JSON, mistral-large-4 kept timing out. Every miss was a cloud invoice: the model quoted the customer line ("Customer: Brightwell Manufacturing") as the site. 2026-11-03
- Fix: the prompt now says the site is where the energy was used (for a cloud invoice, the region line). And if the proposed site line names no known site, code looks for itself: only if the whole document names exactly one known site, it uses the first line naming it as evidence. Two sites, or a disagreement, still means rejected plus a gap. 2026-11-03
- LLM_MODEL = `nvidia/nemotron-3-ultra-550b-a55b`: the most accurate working model, and NVIDIA's own model on NVIDIA's API. Fallback if it is slow or down: `nvidia/nemotron-3.5-bolt-e4b`. Requests time out after 45 s with 3 tries (`CR_LLM_TIMEOUT`, `CR_LLM_ATTEMPTS`); after that, auto mode uses the rules proposer. 2026-11-03
- Bench after the site fix: nemotron-3-ultra-550b-a55b 13/13 exact, 0 rejected (167 s for 13 docs); nemotron-3.5-bolt-e4b 13/13, 0 rejected (117 s). Seed extractions are re-saved with Ultra (`llm:nvidia:nvidia/nemotron-3-ultra-550b-a55b`), so the demo shows real model output and still runs with no key; each cached value is re-verified on every run. 2026-11-03

- Docs: one design/architecture doc per feature in `docs/features/`, updated in the same PR as the code; `tests/test_docs.py` fails the build when docs and code disagree (functions, CLI commands and flags, env vars, paths, schema tables, cache labels, seed counts). One PR per feature from now on. 2026-11-03

- Model-agnostic LLM layer: presets nvidia, anthropic, openai, openrouter, ollama (local, no key) and openai_compatible (any server via `LLM_BASE_URL`); every setting can be overridden per task (`LLM_<FIELD>_<TASK>`, e.g. `LLM_MODEL_EXTRACT`); non-OpenAI SDKs plug in via `register_provider(client_factory=...)`; no default model anywhere (Anthropic's default removed too). Why: the team wants agents that work with any model, and verification by code makes swapping models safe. 2026-11-03

- Background batch run for the orchestrator: prepare (read + propose) in parallel threads with no ledger access, then commit in sorted-path order on the main thread, so ids and GAP numbers don't depend on worker count; one failing file is isolated (`errors`, `ingest_error` event) and nothing half-written remains; the `cr.batch.v1` summary (with a ready-to-post `summary_text`) is stored in the append-only `batch_finished` event, not a new table; `collect_node(state)` is LangGraph-ready without importing LangGraph (the orchestrator is a teammate's). 2026-11-04

- Knowledge graph inside SQLite: two read-only views (`ledger_edges`, `ledger_nodes`) computed from the tables, so the graph is never stale and nothing is stored twice; traversal is one `WITH RECURSIVE` query (out = what this depends on, in = what depends on this) that doesn't walk through shared hubs (person, room, period, run, site); lineage/impact/month graphs with Mermaid + JSON export; gaps link to rows via `refs_json` keys. No graph server (e.g. Neo4j): the close asks short fixed-shape questions, and clone-and-run reproducibility is judged. 2026-11-04

- Graph database: Ujjwal chose to add Neo4j (this supersedes the "no graph server" part of the line above). Neo4j Community in Docker (`infra/neo4j/docker-compose.yml`): most recognizable, built-in browser for the demo, Apache-2.0 driver. Not chosen: Kùzu (archived Oct 2025), its successor LadybugDB (packaging in flux), FalkorDBLite (beta; Apple Silicon needs macOS 26). One graph model: Neo4j mirrors the `ledger_nodes`/`ledger_edges` views exactly (same types, link names upper-cased, same ids), so SQLite stays the system of record and the offline `ledger trace/impact/graph` keep working. Each sync rebuilds the copy in one write transaction (only `CR`-labelled nodes); auto-sync after any `carbonroom` command that grew the event log (`CR_GRAPH=auto|on|off`), and a failed sync never fails the command. New `graphdb` commands: why/conflicts/gaps/find/read-only query/selftest. `graphdb selftest` runs every Cypher query against a live server: 14/14 passed on Neo4j 2026.07.1. The driver switches off Neo4j's "relationship type does not exist" notices (a ledger with no gaps has no gap links, so they fired on every `why`); the tests catch real typos instead. That setting is stable only in driver 6.x, so the driver range is `>=6,<7`. 2026-11-04
